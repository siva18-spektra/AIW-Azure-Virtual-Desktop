## Exercise 1: Understanding Azure Migrate

### What is Azure Migrate?

**Azure Migrate** is a Microsoft service that acts as a **centralized hub** for assessing and migrating on-premises resources to Azure. Instead of using separate, disconnected tools for each type of workload, Azure Migrate brings together assessment and migration capabilities for servers, databases, web applications, virtual desktops, and data — all from one place.

### How Does Azure Migrate Help with VDI Migrations?

Azure Migrate includes a dedicated component built specifically for migrating existing **Virtual Desktop Infrastructure (VDI)** environments. This component uses the **Lakeside SysTrack** digital experience monitoring solution to:

- **Gather data** on your current VDI infrastructure, such as usage patterns, performance, and configuration.
- **Analyze that data** to understand how your existing environment behaves.
- **Recommend the right migration path**, so that your workloads move to Azure Virtual Desktop successfully and with minimal surprises.

Because of this, Microsoft recommends using Azure Migrate whenever you are planning a VDI-to-Azure Virtual Desktop migration.

### What Workloads Can Azure Migrate Assess and Migrate?

Azure Migrate is not limited to virtual desktops — it can assess and migrate several types of on-premises workloads to Azure, as summarized below:

| Workload Type | What Azure Migrate Does |
|---|---|
| **Servers** | Assesses on-premises servers and migrates them to Azure virtual machines. |
| **Databases** | Assesses on-premises databases and migrates them to Azure SQL Database or an Azure SQL Database managed instance. |
| **Web Applications** | Assesses on-premises web applications and migrates them to Azure App Service using the Azure App Service Migration Assistant. |
| **Virtual Desktops** | Assesses your on-premises VDI/RDS environment and migrates it to Azure Virtual Desktop. |
| **Data** | Migrates large volumes of data to Azure quickly and cost-effectively using Azure Data Box products. |

For Contoso's scenario, the **Virtual Desktops** row is the most relevant, since the goal is to move an existing VDI/RDS environment to Azure Virtual Desktop.
